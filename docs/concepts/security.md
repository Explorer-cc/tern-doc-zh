# 信任与安全

安装插件意味着信任它。插件以你的身份运行，拥有与你相同的文件、程序和 shell 访问权限，而 Tern 没有可缩小这些权限范围的权限系统。本页说明信任模型、Luau 沙箱的用途与局限、插件可以访问的内容、远程主机会如何改变情况，以及如何据此安装和编写插件。

## 信任模型

Tern 对待插件的方式，就像 Neovim 对待其 Lua 插件、WezTerm 对待其 Lua 配置一样：它们是你选择运行的代码。没有审核、没有签名、`plugin.toml` 中没有权限列表，也不会在插件执行操作前提示你。软件包一旦放入插件文件夹就会开始运行：`tern plugin install`、`link` 和复制到文件夹中，都会导致重新加载（通过 CLI 或文件夹监视），并运行其中的入口。

| 问题 | 答案 |
| --- | --- |
| 谁决定运行什么？ | 任何能够写入 `<config>/plugins/`，或能够写入 `.path` 文件或符号链接所指向的软件包目录的人 |
| 插件以谁的权限运行？ | 运行该进程的用户：Host 端由会话守护进程运行，Window 端由窗口运行 |
| 运行前会询问什么？ | 什么都不会询问 |
| 如何关闭插件？ | 在 `settings.json` 中设置 `plugins_disabled`（或 `plugins: false`）、移除软件包，或运行 `tern plugin unlink`；已禁用插件的入口不会运行 |

这是有意为之。终端插件之所以有用，是因为它能运行 `kubectl`、读取你的项目文件并向你的 shell 中输入内容；允许这些操作的权限系统几乎起不到限制作用，而不允许这些操作的权限系统则会让插件无法完成工作。

## 沙箱的用途

插件的每一端都在沙箱化的 Luau VM 中运行（[运行时、预算与 JIT](runtime.md#vm)）。沙箱可以防止有缺陷的插件损害 Tern，但无法保护你免受恶意插件侵害。

| 沙箱特性 | 防范 | 无法阻止 |
| --- | --- | --- |
| 没有 `io`、`os.execute`、`os.getenv` 或 `os.remove` | 代码意外绕过 `tern` 的错误处理直接访问系统 | 执行相同操作的 `tern.fs`、`tern.process` 和 `tern.getenv` |
| `require` 限定在软件包目录内 | 模块路径悄然加载其他人的代码 | 对任意文件调用 `tern.fs.read` |
| 内置库只读 | 一个模块破坏其他模块的 `string` 或 `table` | VM 之外的任何事情 |
| 时间预算（4 ms、50 ms、2 s） | 无限循环冻结窗口或工作线程 | 将耗时工作移至进程，或分散到多个定时器中 |
| 256 MiB 内存限制 | 失控增长的 Lua 表耗尽进程内存 | 插件启动的进程 |
| 插件的每一端各使用一个 VM | 一个插件的全局变量或错误影响另一个插件 | 一个插件通过 `tern.fs` 写入另一个插件的软件包或数据文件夹 |

所有访问 VM 外部的途径都由 `tern` 提供，因此 `tern` API 完整列出了插件可以直接执行的操作，而允许的操作范围并不小。

## 插件可以访问的内容

| 可访问项 | Host 端 | Window 端 |
| --- | --- | --- |
| 文件 | `tern.fs` 可读取、写入和删除守护进程用户在主机上有权限访问的任意路径 | 相同操作，但在窗口运行的机器上执行 |
| 程序 | `tern.process.run` 可启动任意程序并传入任意参数，继承守护进程的环境，并额外包含 `TERN_PLUGIN_DATA` | 相同操作，从窗口进程启动，并额外包含 `TERN_WINDOW_KEY`；在 iOS 上会引发错误 |
| 网络 | `tern.fetch` 可从守护进程所在机器发送任意 HTTP(S) 请求，可指定任意方法、标头和正文 | 相同操作，从窗口运行的机器发送，包括 iOS |
| 环境 | `tern.getenv` 读取守护进程的环境 | `tern.getenv` 读取窗口的环境 |
| 系统钥匙串 | 无 | `tern.secrets` 可在系统钥匙串中读写此插件自己的机密信息；不能指定其他插件的机密信息 |
| Shell 输入 | `tern.pane.write` 可向主机上的任意窗格输入内容 | `cx:run` 可向窗口中的任意窗格输入内容，包括远程主机的窗格 |
| 新 shell | `spawn` 过滤器可更改主机启动的每个 shell 的程序、参数、目录和环境 | `cx.layout` 可打开运行命令的标签页和分屏 |
| 你运行的内容 | `command_started` 和 `command_finished` 会携带每条命令行；`tern.pane.list` 会提供每个窗格的目录、程序和标题 | 相同事件，并可通过 `cx.session` 访问窗口中的所有窗格 |
| 命令输出 | Lens 会接收其 `match` glob 所匹配命令的每一行 | 无直接访问方式 |
| 你的窗口 | 显示该窗格的窗口中的效果：提示、剪贴板（`cx:copy`），以及打开路径或 URL（`cx:open`，规则与点击链接相同） | 内置命令覆盖、快捷键绑定、优先接收每次打开操作和链接点击的路由、界面文本，以及作用于 Tern 全部 UI 的样式表 |

`tern.process.run` 接受参数向量并直接启动程序，不经过 shell。`tern.fetch` 可以访问机器能够访问的任意 HTTP(S) 服务器，包括 `localhost` 和本地网络，因此它也是一种让数据离开机器的途径。`curl` 或 `ssh` 等其他程序，也只需一次 `tern.process.run` 调用即可启动。

插件数据也不是私有的。`<state>/plugin-data/<id>/` 和 `kv.json` 都是普通文件，任何以你的身份运行的插件和程序都可以读写。`tern.secrets` 会在系统安全存储中为每个插件保存机密信息（无法使用时则保存为仅所有者可访问的文件），并使用以插件命名的账户（`plugin.<id>.<name>`），因此一个插件的 `tern.secrets` 永远不会返回另一个插件的机密信息。参见[文件、进程与存储](../guides/io.md)。

## 远程主机

窗口连接到另一台机器时，会涉及两组插件，它们运行在不同位置并拥有不同权限：

| 插件 | 运行位置 | 身份 | 可访问内容 |
| --- | --- | --- | --- |
| 远程主机的 Host 端 | 远程机器上的守护进程中 | 运行该守护进程的用户 | 该机器上的文件、程序和窗格 |
| 你的 Window 端 | 你的机器上的窗口中 | 你 | 你的机器，以及窗口中的所有窗格，包括远程窗格 |

远程主机的插件不会在你的机器上运行代码。它们传到你窗口中的内容是数据：其目录（块标题和图标、Lens glob）、块帧、Lens 视图、效果（提示、剪贴板文本、打开操作）以及 manifest 样式；你的窗口会将这些样式安装为全局样式表（`plugin:<host>:<id>:styles`）。远程主机运行哪些插件，由该主机的所有者通过其主机上的插件文件夹决定。

另一方面，你的 Window 端可以跨主机工作：`cx:run` 接受窗口中的任意窗格，因此窗口插件输入到远程 shell 的文本会以该 shell 的权限在那台主机上运行。安装 Window 端插件时，应假定它可以向你打开的每个 shell 输入内容，因为它确实可以。

## 没有权限系统

Tern 不会声明或检查插件能力，也不会就这些能力请求授权；它同样不会为软件包签名或验证。插件可以执行的所有操作，从其入口运行的那一刻起就都可以执行。现有控制手段都较为粗略：

- 在 `settings.json` 中设置 `plugins: false`，即可不在那台机器上加载任何插件。
- `plugins_disabled` 可阻止列出的插件加载；“偏好设置 › 插件”中为每个插件提供了开关。
- 每台机器读取各自的设置和插件文件夹：在你的 Mac 上禁用插件不会让远程主机也禁用它，反过来也一样。

参见[包与清单](packages.md#设置)。

## 建议

**安装。**

- 安装前阅读插件：`plugin.toml`、两个入口、它们 `require` 的每个模块，以及所有 `tern.process.run`、`tern.fetch`、`tern.fs.write`、`tern.fs.remove`、`tern.pane.write` 和 `cx:run` 调用。
- 安装你读过的代码。使用 git URL 运行 `tern plugin install` 会浅克隆当时默认分支上的内容，因此安装的内容可能与之前审核过的内容不同。若要固定到某次提交，请自行克隆仓库，检出你审核过的提交，然后从该目录安装：

  ```sh
  git clone https://github.com/example/tern-k8s
  git -C tern-k8s checkout 3f2a9c1
  tern plugin install ./tern-k8s
  ```

  安装的副本不包含 `.git`，也不会自行更新；之后运行 `tern plugin install --force` 会替换它。
- 插件文件夹及其中链接到的所有目录，都应仅允许你写入：写入其中的任何内容都会在下次重新加载时运行。
- `tern plugin list` 和“偏好设置 › 插件”会显示已加载的内容。若不确定某个插件是否安全，请禁用它，不要让它继续运行。

**开发。**

- 使用 `tern plugin link DIR` 开发插件：Tern 会从你的检出目录加载插件，并在每次保存时重新加载；`tern plugin unlink ID` 可将其移除。参见[分发](../guides/distribution.md)。
- 将窗格输出、命令行、文件名和 Lens 输入都视为不可信文本。不要在未按 Shell 规则正确引用这些文本的情况下，用它们拼接 `cx:run` 或 `tern.pane.write` 字符串，因为这些文本会在用户的 shell 中运行；优先使用带参数向量的 `tern.process.run`。
- 不要将机密信息放在 `tern.kv` 和数据文件夹中，因为它们是普通文件：应通过 `tern.secrets` 存储（用于 Window 端）；它会在系统钥匙串中使用插件自己的账户保存每个插件的机密信息。参见[`tern.secrets`](../reference/api-window.md#tern-secrets)。
- 在 README 中说明插件会运行哪些程序、会联系哪些服务器、会写入哪些文件，方便用户快速审核。
