# 任务管理器

`procs` 用于打开和驱动任务管理器块：实时进程、机器仪表、平铺或树状排列、筛选和进程选择。你可以用它捕获进程视图，或打开所选进程的菜单和退出确认。

## 打开块

| 命令 | 作用 |
| --- | --- |
| `procs open` | 在聚焦窗格旁打开任务管理器块并聚焦。等待首个样本显示。 |

新块以按 CPU 使用率排序的平铺列表开始，最繁忙的进程排在前面。它会列出该窗格所属主机的进程，不一定是窗口所在机器的进程。样本为实时数据，无头运行中也如此；没有进程测试夹具。

`open` 会实时等待采样，适用脚本的 20 秒超时，然后稳定处理 450 毫秒。本地采样取决于平台支持情况；远程采样需要连接到支持进程列表的主机。无法获得样本时，`open` 可能一直等待直到超时。这些命令并非仅用于无头运行；脚本实现使用原生代码，而不是 Web 客户端。

`tern ctl state` 会在 `task_manager_blocks.blocks[]` 中记录块，其中包括 `id` 和 `sampled`。容器对象还会报告 `paused`、`interval_ms` 和本地样本的 `seq`。当当前标签页中可见该机器的块且更新未暂停时，采样器会运行。

## 排列和筛选

| 命令 | 作用 |
| --- | --- |
| `procs sort name\|pid\|user\|cpu\|memory\|gpu\|threads\|disk` | 按该列对聚焦的任务管理器块排序；重复选择当前列会反转顺序。 |
| `procs tree on\|off` | 将子进程嵌套在父进程下，或恢复平铺列表。 |
| `procs filter ["<text>"]` | 设置筛选内容；省略或空文本会清除筛选。 |

选择其他列时，名称、PID 和用户默认升序；CPU、内存、GPU、线程数和磁盘默认降序。树状视图中会对同级项排序。筛选不区分大小写，会匹配名称、用户或命令行；全数字筛选也会匹配 PID 开头。

除 `open` 外，所有命令都要求聚焦任务管理器块，否则会报错 `no task-manager block has focus`。缺少或未知的排序列以及无效的树视图值会导致解析错误。每条命令都会稳定处理 450 毫秒，而不会等待新样本。

每个块的状态字段为 `sort`、`descending`、`tree`、`filter` 和 `rows`（排列后的行数）。排序和树状模式是共享会话状态；筛选和选择属于当前窗口。

## 选择和操作

| 命令 | 作用 |
| --- | --- |
| `procs select ["<name>"]` | 只选择名称完全匹配的第一条可见行，并滚动到该行。 |
| `procs menu` | 为所选进程行打开菜单。 |
| `procs quit [force]` | 请求退出所选进程；`force` 表示请求强制退出。 |

选择会搜索当前排列的行，因此筛选或折叠的树分支可能会隐藏目标。没有样本时会报错 `no sample yet`；没有名称完全匹配的行时会报错 `no row is called …`。省略名称会按空名称处理，不表示清除选择。

`quit` 会打开确认框，而不是立即发送信号；未选择进程时不执行操作。确认 Quit 会发送终止请求；Force Quit 会杀死目标进程。在 Windows 上，Quit 使用进程终止操作。对于远程块，信号会发送到对应主机。使用测试框架的 `dialog` 命令回答确认。命令会稳定处理 450 毫秒，不会等待进程退出。

块的 `selected` 状态字段包含所选 PID。菜单和待处理确认要通过控制端点的 `menus` 和 `system` 命令检查，不在任务管理器额外字段中提供。

解析器会忽略 `open`、`sort`、`tree` 和 `menu` 后面的多余词。对于 `quit`，只有紧随其后的词恰好是 `force` 才启用强制退出；其他词仍会解析为普通 Quit。`filter` 和 `select` 会将其余所有词作为文本，因此名称和筛选内容包含空格时请加引号。

## 示例

按 procs-tree golden 所示，将完整标签页显示为按内存排序的进程树：

```text
ready
procs open
zoom
procs tree on
procs sort memory
wait 2500
shot procs-tree
```

选择 Tern 进程并显示其详情，如 procs golden 所示。要求有一条名称恰好为 `tern` 的已显示进程：

```text
ready
procs open
wait 2500
procs select "tern"
wait 450
shot procs
```

额外等待可让实时样本累积；不能因此令进程名称、PID 或使用率变为确定值。
